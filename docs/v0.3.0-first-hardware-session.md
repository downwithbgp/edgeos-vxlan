# v0.3.0 — first hardware qualification session

**Status:** procedure prepared; **not executed**. No hardware has been changed, rebooted,
upgraded or installed.

**Purpose:** execute the bounded first hardware session only: inventory, backup, package staging,
installation, and isolated `vxlan903` testing. This session deliberately stops before production
migration (`vxlan41913`), reboot, package removal, failure injection, external/Internet probes,
tagging or publishing.

**Artifacts:** package version `0.3.0~rc3+edgeos3.0.1.e50`; the RC3 `.deb` files and their
SHA-256 values are recorded in `docs/v0.3.0-rc3-artifacts.md`. Do not start without that record and a matching `SHA256SUMS` file.
The helper cross-checks the staged hashes; compare them manually with the artifact record as well.

**Helper:** `scripts/first-hardware-session.sh`. It never saves the configuration, reboots, removes
packages, or touches `vxlan41913`.

## 0. Preconditions and stop line

* **Platform:** Ubiquiti EdgeRouter X / ER-e50, EdgeOS 3.0.1 build 5862409,
  Linux `4.14.54-UBNT`, MIPS little-endian. Do not install on another model, firmware or kernel.
* **Management path:** independent of `vxlan41913`; verify it before starting. A console is
  available but this session does not reboot.
* **Isolated peer:** a local VTEP peer B on the underlay and a routed client host C on the router's
  LAN side. The local VTEP is the **isolated dataplane** class; it is not the remote Route64 VTEP
  and proves nothing about Route64 or the Internet path.
* **Router:** use the existing ER-X. Controlled network interruptions, interface recreation,
  configuration rollback, package upgrades and eventual reboot testing are acceptable homelab
  activity. Preserve a management/recovery path, capture the state and keep off-router backups;
  ordinary homelab downtime is not a release-blocking risk. Avoid unnecessary global
  interventions. The production interface `vxlan41913` must not be changed in this session.
* **Do not, at any point in this session:**
  * modify `vxlan41913` or its manual `HEv6`/interface-scoped rules;
  * `save` the configuration;
  * reboot;
  * remove, purge or downgrade packages;
  * run failure injection, global interventions or external/Internet probes;
  * tag, merge or publish a release.
* **Session directory:** use one directory, for example
  `SESSION=/config/rc3-sessions/$(date -u +%Y%m%dT%H%M%SZ)`, and pass `--session "$SESSION"` to every
  helper phase. Copy it off-router before cleanup. The backup archive excludes the `rc3-sessions`
  evidence tree, so it never includes itself.

## 1. Inventory (read-only)

```bash
export SESSION=/config/rc3-sessions/$(date -u +%Y%m%dT%H%M%SZ)
sudo scripts/first-hardware-session.sh inventory --session "$SESSION"
```

Review `$SESSION/inventory/inventory.txt` and `$SESSION/inventory/vxlan41913-rules.txt`:

* firmware, kernel, package versions and diversions;
* existing VXLAN interfaces and their state;
* `show configuration commands`;
* the IPv4/IPv6 filter state and the manual `vxlan41913`/`HEv6` rules with their order;
* runtime-only IPv6 policy routing, the dedicated table, the delegated-prefix loopback address and
  the interface-specific sysctls (these are captured but not restored in this session);
* the management path does not depend on `vxlan41913`.

**Gate 1:** the manual `vxlan41913` rules are captured completely, the management path works, and
no unexpected package or diversion is present. Otherwise stop.

## 2. Backup

```bash
sudo scripts/first-hardware-session.sh backup --session "$SESSION"
```

The helper writes `$SESSION/backup/config.boot`, a `/config` archive, the inventory, raw and
normalized firewall captures, and a `SHA256SUMS`. The archive excludes the `rc3-sessions` evidence
tree (avoiding self-inclusion) and the helper validates that it contains `config.boot` and can
restore it. Copy the backup off-router immediately:

```bash
scp -r root@<router>:$SESSION/backup <workstation>/rc3-session-backup
cd <workstation>/rc3-session-backup && sha256sum -c SHA256SUMS
```

**Gate 2:** the off-router copy verifies. Keep it for the whole session.

## 3. Package staging

On the workstation, copy the RC3 artifacts and `SHA256SUMS` to the router:

```bash
scp edgeos-vxlan-kmod_<version>_mipsel.deb \
    edgeos-vxlan_<version>_all.deb \
    SHA256SUMS \
    root@<router>:/config/rc3-artifacts/
```

On the router:

```bash
sudo scripts/first-hardware-session.sh stage --session "$SESSION" \
    --artifacts /config/rc3-artifacts
```

The helper verifies the exact RC3 package names, version `0.3.0~rc3+edgeos3.0.1.e50`,
architectures (`mipsel`/`all`) and recorded SHA-256 values, then prints the metadata, the free disk
space and the `sha256sum -c SHA256SUMS` result when the file is present.

**Gate 3:** the exact RC3 package names, version, architectures and recorded hashes match
`docs/v0.3.0-rc3-artifacts.md`, and there is enough free space. Do not install otherwise.

## 4. Installation

```bash
sudo scripts/first-hardware-session.sh install --session "$SESSION" \
    --artifacts /config/rc3-artifacts --execute
```

The helper installs `edgeos-vxlan-kmod` and `edgeos-vxlan` in **one** `dpkg` transaction (kmod
first), then verifies:

| Check | Pass criterion |
|---|---|
| Packages | both `install ok installed` |
| Diversion | `/opt/vyatta/share/perl5/Vyatta/Interface.pm` is diverted to `.edgeos-vxlan-original` |
| Existing VXLAN interfaces | unchanged by the install (no recreation; same links) |
| IPv4/IPv6 filter tables | unchanged by the install after volatile-counter normalization; raw captures are retained separately |
| Manual `vxlan41913`/`HEv6` rules | unchanged by the install |

**Gate 4:** all checks pass. If `dpkg` or any verification fails: **stop**, do not remove packages,
keep `$SESSION/install/` (including `dpkg.log`, the pre/post normalized diffs, the raw firewall
captures and package state), and report. Package removal is a later, separately approved decision.

## 5. Isolated VXLAN testing (`vxlan903`)

### 5.1 Configure the isolated interface and rulesets

Use a local VTEP peer B and a routed client C. Replace the placeholders with the test environment's
values; do not use `vxlan41913`.

```text
configure

set interfaces vxlan vxlan903 vni 903
set interfaces vxlan vxlan903 local-ip <underlay-local>
set interfaces vxlan vxlan903 remote-ip <local-peer>
set interfaces vxlan vxlan903 port 4789
set interfaces vxlan vxlan903 mtu 1450
set interfaces vxlan vxlan903 address 198.51.100.1/24
set interfaces vxlan vxlan903 address 2001:db8:903::1/64

set firewall name VXLAN903_IN default-action drop
set firewall name VXLAN903_IN rule 10 action accept
set firewall name VXLAN903_IN rule 10 protocol icmp
set firewall name VXLAN903_IN rule 20 action accept
set firewall name VXLAN903_IN rule 20 state established enable
set firewall name VXLAN903_IN rule 20 state related enable

set firewall name VXLAN903_LOCAL_IN default-action drop
set firewall name VXLAN903_LOCAL_IN rule 10 action accept
set firewall name VXLAN903_LOCAL_IN rule 10 protocol icmp
set firewall name VXLAN903_LOCAL_IN rule 20 action accept
set firewall name VXLAN903_LOCAL_IN rule 20 state established enable
set firewall name VXLAN903_LOCAL_IN rule 20 state related enable

set firewall name VXLAN903_OUT default-action drop
set firewall name VXLAN903_OUT rule 10 action accept
set firewall name VXLAN903_OUT rule 10 protocol icmp
set firewall name VXLAN903_OUT rule 20 action accept
set firewall name VXLAN903_OUT rule 20 state established enable
set firewall name VXLAN903_OUT rule 20 state related enable

set firewall ipv6-name VXLAN903_OUT6 default-action drop
set firewall ipv6-name VXLAN903_OUT6 rule 10 action accept
set firewall ipv6-name VXLAN903_OUT6 rule 10 protocol icmpv6
set firewall ipv6-name VXLAN903_OUT6 rule 20 action accept
set firewall ipv6-name VXLAN903_OUT6 rule 20 state established enable
set firewall ipv6-name VXLAN903_OUT6 rule 20 state related enable

set firewall ipv6-name VXLAN903_IN6 default-action drop
set firewall ipv6-name VXLAN903_IN6 rule 10 action accept
set firewall ipv6-name VXLAN903_IN6 rule 10 protocol icmpv6
set firewall ipv6-name VXLAN903_IN6 rule 20 action accept
set firewall ipv6-name VXLAN903_IN6 rule 20 state established enable
set firewall ipv6-name VXLAN903_IN6 rule 20 state related enable

set firewall ipv6-name VXLAN903_LOCAL_IN6 default-action drop
set firewall ipv6-name VXLAN903_LOCAL_IN6 rule 10 action accept

set firewall ipv6-name VXLAN903_LOCAL_IN6 rule 20 action accept

set interfaces vxlan vxlan903 firewall out name VXLAN903_OUT

```

This is a **commit**, not a save. The reconciler applies the dispatch, runs its gate, and leaves
`vxlan903` down if any attachment is not effective.

### 5.2 Structural verification

```bash
sudo scripts/first-hardware-session.sh verify --session "$SESSION"
```

The helper checks that:

* `vxlan903` exists and is administratively up (the exact `UP` flag, not a `LOWER_UP` substring);
* the six configured attachments are present, including IPv6 `out`;
* there is exactly one exact dispatch per direction/family in the native hooks, including
  `VYATTA_FW_OUT_HOOK -o vxlan903 -j VXLAN903_OUT6`;
* `INPUT`/`FORWARD` reach the `VYATTA_FW_*` hooks, including IPv6 `FORWARD` to the out hook;
* the last rule of each target chain is the vendor default-action rule for `drop`
  (`-A <chain> -m comment --comment "<chain>-<n> default-action drop" -j DROP`);
* no manual `vxlan903` rule exists in a base chain;
* the manual `vxlan41913`/`HEv6` rules are unchanged.

For the authoritative gate, also run the helper in a configuration session:

```text
configure
# the helper needs the configuration-session environment
sudo -u vyattacfg -E /opt/vyatta/sbin/vyatta-vxlan-firewall --verify-all vxlan903
exit
```

**Gate 5a:** structural verification PASS. A failure means the commit's fail-closed behavior is
being exercised: capture the state and clean up (see §7); do not force the interface up.

### 5.3 Dataplane matrix (isolated dataplane class)

The local VTEP is a test fixture. These probes prove the isolated dataplane; they do not prove
Route64 or the Internet path.

| Direction | Hook/path | Traffic | Positive control | Negative control |
|---|---|---|---|---|
| `in` | `FORWARD -i vxlan903` | B → A → C (forwarded ingress) | a permitted protocol/port reaches a verified listener on C and increments the native chain | a denied protocol/port does not reach it and increments the drop counter |
| `out` (IPv4) | `FORWARD -o vxlan903` | C → A → B (forwarded egress) | permitted reaches a verified listener on B | denied does not reach it |
| `out` (IPv6) | `FORWARD -o vxlan903` | C → A → B (forwarded egress) | permitted IPv6 reaches a verified listener on B | denied IPv6 does not reach it |
| `local` (IPv4/IPv6) | `INPUT -i vxlan903` | B → A's own overlay address (router-destined) | permitted reaches the router | denied does not |

Repeat for IPv4 and IPv6. Start a real listener on the destination and prove the positive control
through the same path before asserting a negative result. Record timestamps, counters and packet
captures. Verify that the outer underlay UDP/4789 traffic is untouched and that an unrelated
interface's policy is unchanged.

### 5.4 Isolated lifecycle checks (optional, isolated interface only)

* **Single replacement (nondisruptive):** add `VXLAN903_IN_B` with the same policy, change
  `firewall in name` to it, and commit while a continuous positive/negative probe runs. The commit
  must succeed, the interface must not be recreated (ifindex unchanged), the dispatch must be
  replaced, and no denied probe may succeed. Restore `VXLAN903_IN` afterwards or leave the state for
  cleanup.
* **Single removal (quiesced):** remove the `out` attachment and commit. The helper quiesces the
  interface, removes the dispatch, and the reconciler reactivates it. Verify the down/up ordering and
  that no packet traverses while the policy is absent. The cleanup in §5.5 removes the whole test
  interface, so the `out` attachment does not need to be restored.

### 5.5 Cleanup (do not save)

Print the two configuration blocks:

```bash
sudo scripts/first-hardware-session.sh cleanup --session "$SESSION"
```

Apply them interactively in the order printed:

1. delete `interfaces vxlan vxlan903` and `commit` (the reconciler removes the dispatch);
2. delete the six `VXLAN903_*` rulesets (including `VXLAN903_OUT6`) and `commit`.

Then verify:

```bash
sudo scripts/first-hardware-session.sh cleanup-check --session "$SESSION"
```

**Gate 5b:** `cleanup-check` PASS: the interface, its dispatch and its rulesets are gone. Do **not**
save; the saved configuration remains the pre-session baseline.

DEFERRED, not inferred from another class.

## 7. Stop, abort and rollback

* **Installation failure:** stop; do not remove packages; keep the session and report. Removal or a
  downgrade is a separate decision with its own approval.
* **Isolated commit or gate failure:** do not save; capture the configuration, link state and
  firewall; delete the test interface (commit) and then the test rulesets (commit); run
  `cleanup-check`; report. The helper's fail-closed behavior may have left `vxlan903` down; do not
  force it up.
* **Probe failure:** stop; do not proceed to another phase; capture and clean up.
* **Any change to `vxlan41913` or its manual rules:** stop immediately and restore from the
  off-router backup using the procedure in `docs/v0.3.0-hardware-acceptance.md`. Do not save.
* **Do not reboot** in this session. Runtime-only state (policy routing, table, loopback address,
  sysctls) is captured but not restored because no reboot is part of this session.
