## 5. Migration of the manually protected `vxlan41913`

The production interface currently has manual IPv6 INPUT/FORWARD jumps to `HEv6_LOCAL`/`HEv6_IN` and
interface-scoped IPv4 INPUT/FORWARD DROP rules. These precede the `VYATTA_FW_*` hooks, so they
**shadow** native enforcement and make a counter-based proof of the native path impossible. The
procedure in the hardware runbook (§6) is a quiesced, fail-closed handover:

1. Capture the exact manual rules and their **order** relative to `VYATTA_FW_*`; capture full
   `iptables-save`/`ip6tables-save` off-router.
2. Create the native rulesets for **both families and both ingress directions**:
   `HEv6_IN_NATIVE`, `HEv6_LOCAL_NATIVE` and `VXLAN41913_IN4` (`default-action drop`, attached to
   both `in` and `local`). Do not attach yet.
3. Quiesce the interface (`set ... disable` + commit); confirm it is down.
4. Remove the manual IPv4 DROP rules and the manual IPv6 jumps **while down** — no exposure, and no
   attempt to prove the native path through a shadowed hook.
5. Attach all four native directions while still down. The reconciler's gate proves the structural
   state: exact dispatch, hook reachability, non-empty chain with a terminal default.
6. Activate (`delete ... disable` + commit) and prove the **native-only** dataplane with counters and
   permitted/denied probes; the manual rules are gone, so counters are meaningful.
7. Rollback quiesces, restores the manual rules, verifies them, removes the native enforcement, and
   only then reactivates. The filtered `iptables-restore --noflush` concept is retained.

## 6. Recovery and rollback

The full procedure is in `docs/v0.3.0-hardware-acceptance.md` §9. The invariants:

* management is via a physical/VLAN interface or console, never `vxlan41913`;
* a failed commit leaves the interface down rather than up without its gate;
* to return to an unfiltered interface, **detach** the native attachment and commit; do not force it
  up manually;
* to recover the manual migration, restore the saved manual rules with a filtered
  `iptables-restore --noflush`, not a full-table restore;
* runtime IPv6 policy-routing rules/table are **not** owned by `edgeos-vxlan` and must be reapplied
  after every reboot before diagnosing tunnel connectivity;
* if the engine is wedged, use the console and the previous configuration revision or the off-router
  `/config/config.boot` copy; reboot only with console access.
