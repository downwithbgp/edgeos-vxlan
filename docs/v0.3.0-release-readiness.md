## 1. What is complete

### Platform investigation and architecture

* The official EdgeOS 3.0.1.5862409 rootfs was inspected: per-interface-type firewall templates,
  `ubnt-fw update-interface`, the Vyatta hook chains, ruleset chains, commit priorities, and the boot
  loader were examined.
* `ubnt-fw` was exercised under qemu for the ruleset validation path; it accepts `vxlanN` names and
  has no interface-type table. No vendor binary patch is needed.
* The `ip -d` human-output defect was reproduced under qemu and traced to the vendor's MIPS
  `print_uint`/variadic path; `ip -j -d` is correct and is the path the reconciler uses.
* The `exists` vs `existsEffective` behaviour in a currently executing commit subtree was established
  empirically and is pinned by a template test.
* An architecture decision record and a platform investigation record are committed.

### Implementation

* `interfaces vxlan vxlanN firewall in|out|local name|ipv6-name` configuration subtree, with:
  * tab completion from the configured rulesets;
  * ruleset-name syntax validation;
  * commit-time ruleset reference and bridge-membership validation;
  * no `priority` declarations, so the work stays in the interface commit unit.
* `vyatta-vxlan-firewall` helper:
  * `--capture`, `--apply`, `--restore`, `--verify-all`, `--remove-all`, `--status`, `--validate`;
  * dispatch verification with `iptables -C` / `ip6tables -C`;
  * exact pre-change snapshot for rollback;
  * bounded direct reinsertion when the old ruleset is no longer configured but its chain exists;
  * fail-closed handling for a new attachment that cannot be established, and for a failed restore.
* Reconciler:
  * captures the live interface state and firewall dispatch before mutation;
  * applies and verifies the desired attachment set before creating or recreating the netdevice;
  * verifies again immediately before bringing the interface up;
  * restores the firewall dispatch during rollback;
  * removes dispatches only after a successful interface deletion;
  * restores the previous dispatch after a failed mutable-only commit.
* Bridge safety:
  * firewall attachments on VXLAN bridge ports are rejected by the firewall helper and by the bridge
    validator;
  * no global bridge netfilter is enabled.
* Packaging:
  * helper and templates installed by `edgeos-vxlan`;
  * dependencies on `vyatta-cfg-firewall` (exact supported version) and `iptables`;
  * removal refused while saved VXLAN configuration or live VXLAN interfaces exist;
  * kernel module payloads and the CVE-2022-50405 backport unchanged.
* Documentation:
  * README native firewall section: syntax, directions/families, routed/bridged semantics,
    underlay/overlay boundaries, lifecycle/failure behavior, upgrade, troubleshooting, limitations;
  * generic IPv6 tunnelbroker example with documentation addresses, underlay peer filtering,
    IPv6 overlay policy, inner IPv4 block, MTU guidance and verification;
  * `ip -d` defect and checksum-offload guidance.

## 3. Deferred, unverified, and blocked

### Hardware acceptance — not executed

The procedure in `docs/v0.3.0-hardware-acceptance.md` has **not** been run. The following cannot be
claimed until it is:

* the real MIPS `ubnt-fw`/iptables path on the router;
* cold boot and saved-configuration restoration with attachments;
* the continuous negative probe for transient fail-open windows during boot, recreation and policy
  replacement;
* attachment replacement/deletion with a static ruleset (the emulator's static-ruleset limitation);
* commit-confirm and rollback;
* upgrade from v0.2.2 with a live tunnel and package removal safeguards;
* Route64 application connectivity, NDP and FDB behavior on the real deployment;
* the vendor `ip -d` defect on the router (already reproduced under qemu, but not on the router).

### Deferred by scope

* Bridged L2 firewall enforcement (attachments rejected; no bridge netfilter).
* `modify`/`ipv6-modify` (mangle) attachments for VXLAN.
* Automatic policy generation.
* Dynamic VTEP discovery, BGP EVPN, multipoint control planes.
* BFD/tunnel health monitoring.
* Encrypted/authenticated VXLAN.
* Hardware VXLAN acceleration.
* Additional EdgeRouter models or EdgeOS releases.
* Replacing the platform iproute2 to fix the cosmetic `-d` output.
* Source-address-dependent IPv6 routing (a separate extension; not coupled to VXLAN).

### Release actions withheld

* No final v0.3.0 tag.
* No published release assets.
* `install.sh`, `SHA256SUMS` and the README install links remain at v0.2.2.
* `docs/release-notes-v0.3.0.md` is intentionally not written until hardware acceptance is reviewed.

## 4. Residual risks

| Risk | Current mitigation | Remaining exposure |
|---|---|---|
| Boot ordering installs the dispatch after the interface is up | The reconciler applies attachments before creating the interface and gates before up; emulated engine verified | A boot-time fail-open window cannot be excluded until the continuous-probe hardware test |
| Engine continues after a failed child action | Parent gate verifies and takes the interface down | The gate runs on vxlan subtree commits; a non-atomic partial commit can still leave configuration drift (existing project rule: do not save after a failed commit) |
| Static-ruleset attachment on a real router | Vendor templates rely on the same `ubnt-fw` path; emulator limitation documented | Hardware Phase 4 must confirm |
| Firewall ruleset deleted in the same commit as a recreation failure | Restore falls back to a direct jump only if the chain still exists; otherwise the interface stays down | Operator must re-commit after fixing the ruleset |
| Package removal leaves a live interface | `prerm` refuses while saved config or live VXLAN interfaces exist | Hardware Phase 8 must confirm the exact `ip link show type vxlan` behavior on EdgeOS |
| `out` semantics misunderstood | Documented as forwarded-only; netns test verifies local traffic is not matched | Operator documentation/training |
