## 4. Isolated dataplane matrix

Fixture: router A, a local VTEP peer B on the underlay, and a routed client C on the router's LAN
side. B and C each ran verified listeners on `tcp/8080` (permitted by the rulesets) and `tcp/9090`
(denied) before any positive control. Overlay addresses are the documentation ranges
`198.51.100.0/24` and `2001:db8:903::/64`; underlay and client addresses are omitted here.

| Combination | Path | Positive control | Negative control | Native counters |
|---|---|---|---|---|
| `in` IPv4 | `FORWARD -i vxlan903` | echo 2/2; `tcp/8080` connected | `tcp/9090` no connection, timeout | rule 10 and rule 20 increment; only the default-action `DROP` increments for 9090; hook = sum |
| `out` IPv4 | `FORWARD -o vxlan903` | echo 2/2; `tcp/8080` connected | `tcp/9090` timeout | as above, egress direction |
| `local` IPv4 | `INPUT -i vxlan903` | echo 2/2; `tcp/8080` connected | `tcp/9090` timeout | as above, router-destined |
| `in` IPv6 | `FORWARD -i vxlan903` | ICMPv6 echo 2/2; `tcp/8080` connected | `tcp/9090` timeout | as above (IPv6 chains) |
| `out` IPv6 | `FORWARD -o vxlan903` | ICMPv6 echo 2/2; `tcp/8080` connected | `tcp/9090` timeout | as above (IPv6 chains) |
| `local` IPv6 | `INPUT -i vxlan903` | ICMPv6 echo 2/2; `tcp/8080` connected | `tcp/9090` timeout | as above (IPv6 chains) |

Counters were zeroed immediately before each block. In every block the permitted rules' counters
incremented, the denied probes left the permitted counters untouched and incremented only the
terminal default-action `DROP`, and each hook counter equalled the sum of its chain's rule counters.
IPv6 neighbour resolution on the overlay worked (echo replies returned over the tunnel).

## 8. Lifecycle phase (hq_06) — findings so far

The lifecycle phase is **incomplete**. Hardware findings so far:

* Scripted (script-template) commits are subject to the platform limitation recorded in
  `docs/v0.3.0-edgeos-scripted-commit-limitation.md`: create+attach in one scripted commit fails
  closed at the interface hook (`firewall ruleset '<name>' is not configured under firewall name`).
* A ruleset created by a commit **without** an attachment is not registered in the vendor engine's
  tree file (`/var/run/vyatta_fw_trees` stayed empty for it); a later attach is refused by the engine
  (`native firewall engine failed to install name attachment ...`). The vendor-supported path is
  create+attach in one **interactive CLI** commit.
* Interactive CLI commits create rulesets correctly, but long commits were repeatedly cut by the
  session harness (ssh pty completion and the host call cap), leaving transient or orphaned state.
  Every such state was cleaned up; one run committed the ruleset (9 configuration lines, chain with
  rules) but did not complete the attachment apply.
* **Replacement (4.1) passed:** the `in` dispatch was replaced with a second policy-equivalent
  ruleset under a 100 ms probe (`8080 OK=230 FAIL=0`, `9090 LEAK=0`), the ifindex stayed 23, and the
  new chain's counters moved. The restore to the original ruleset required the interactive path; a
  scripted restore while the new dispatch was current was refused by the vendor engine.
* **Removal (4.2) did not pass and exposed a real transition defect:** removing the two `out`
  attachments under the probe produced `8080 OK=37 FAIL=98` and **`9090 LEAK=3`**, and the interface
  remained up with the `out` dispatch removed for a window; the commit also left a partial attachment
  set (`firewall out` node present, one child applied) when the session was cut. All six attachments,
  the v4/v6 jumps and the dataplane were restored afterwards (link UP; `8080` connects and `9090`
  times out for `in`, `local` and `out`).
* When a sibling chain was transiently absent, the helper failed closed and took the interface down;
  enforcement was restored before continuing.
* The vendor's commit-phase firewall apply rebuilds chains and can transiently remove a sibling
  chain; the helper's gate detects this and refuses. A ruleset-only commit in a scripted session can
  degrade an attached ruleset without invoking the interface hook — a platform-level exposure that
  also affects native interfaces (see the limitation record).

Remaining lifecycle steps — replacement verification, removal, administrative state, recreation and
`commit-confirm` rollback — need an interactive session harness that lets the commit run to
completion. The production migration of `vxlan41913`, reboot/fail-open testing and external probes
were not started.
