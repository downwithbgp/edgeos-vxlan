## Intended policy (preserved, not redesigned)

The manual policy was: interface-scoped IPv4 `DROP` in `INPUT`/`FORWARD`; interface-scoped IPv6
`INPUT`/`FORWARD` jumps to the `HEv6_LOCAL`/`HEv6_IN` chains (related/established and ICMPv6
accepted, default drop). The `HEv6_*` chains and their `tun0` jumps are shared with the HE tunnel
and were preserved.

Native rulesets created interactively (firewall rulesets must not be created by a scripted session):

* `VXLAN41913_IN4` — default-action drop (IPv4 `in` and `local`).
* `HEv6_IN_NATIVE`, `HEv6_LOCAL_NATIVE` — rule 10 related/established accept, rule 20 ICMPv6
  accept, default-action drop.

Four attachments: IPv4 `in`/`local` → `VXLAN41913_IN4`; IPv6 `in` → `HEv6_IN_NATIVE`; IPv6 `local`
→ `HEv6_LOCAL_NATIVE`. No `out` policy (the production intent filters ingress only).

## Handover and deviations

1. `vxlan41913` quiesced (`disable`); the interface went down.
2. The four interface-scoped manual rules were removed while down; `v4_left=0`, `v6_left=0` for
   `vxlan41913`; the `tun0` `HEv6` jumps remained.
3. **Deviation:** the first attach commit failed with
   `ERROR: native firewall engine failed to install name attachment 'VXLAN41913_IN4' on vxlan41913 (in)`.
   The vendor engine did not accept the rulesets when the attachment was applied by the interface
   hook. `ubnt-fw update-interface update` for all four attachments **inside a configuration
   session** returned 0, and the attachment configuration commit then succeeded (`attachments=4`).
   This is the same vendor registration behaviour recorded for the test interface: a ruleset created
   by an earlier commit is not accepted by the engine until it is materialised in a session context.
4. `--status` and `--verify-all vxlan41913` pass (configured/effective pairs, gate).

## Activation and validation

interface-scoped rules; no manual `vxlan41913` rule remains.
