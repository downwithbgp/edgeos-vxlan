# v0.3.0 hardware acceptance procedure

**Status:** procedure prepared; **not executed**. No hardware was changed, rebooted, upgraded or
installed by the implementation work.

**Purpose:** establish that native firewall attachments on a routed VXLAN interface enforce the
intended policy in the dataplane across the supported lifecycle, and that no operational-but-unfiltered
interval can be observed.

**Supported platform:** Ubiquiti EdgeRouter X / ER-e50, EdgeOS 3.0.1 build 5862409, Linux
4.14.54-UBNT, MIPS little-endian.

## 0. Safety and preconditions

* Use a **disposable test router** or a maintenance window approved by the maintainer. Do not run
  these steps on a production router without explicit approval.
* Take a full configuration backup and a copy of `/config/config.boot`; record `show version`,
  `show configuration commands`, `iptables-save`, `ip6tables-save`, `ip -d link`, `ip -6 neigh`.
* Use documentation address ranges and a disposable VNI/port (for example VNI 903, port 4789, overlay
  `198.51.100.0/24` and `2001:db8:903::/64`). Do not publish the maintainer's real endpoints, MAC
  addresses or firewall policy.
* Have a second host or network namespace on the underlay and a host on the overlay that can send
  continuous probes. The probe host must not be the router.
* Confirm the recovery path: console access, package rollback commands, and the ability to restore
  the saved configuration.
* Do not remove the existing IPv4/IPv6 VXLAN regression configuration until Phase 9 is complete.

## 3. Native attachment — routed VXLAN

Use a disposable routed VXLAN interface `vxlan903` with an IPv4 underlay and an IPv6 overlay (or the
dual-family test topology). Create policies that make permitted and denied traffic unambiguous.

```text
configure

# IPv4 overlay policy: deny by default, allow ICMP echo and established/related.
set firewall name VXLAN903_IN default-action drop
set firewall name VXLAN903_IN rule 10 action accept
set firewall name VXLAN903_IN rule 10 protocol icmp
set firewall name VXLAN903_IN rule 20 action accept
set firewall name VXLAN903_IN rule 20 state established enable
set firewall name VXLAN903_IN rule 20 state related enable

# IPv6 overlay policy: deny by default, allow NDP and ICMPv6 echo, allow established/related.
set firewall ipv6-name VXLAN903_IN6 default-action drop
set firewall ipv6-name VXLAN903_IN6 rule 10 action accept
set firewall ipv6-name VXLAN903_IN6 rule 10 protocol icmpv6
set firewall ipv6-name VXLAN903_IN6 rule 20 action accept
set firewall ipv6-name VXLAN903_IN6 rule 20 state established enable
set firewall ipv6-name VXLAN903_IN6 rule 20 state related enable

set interfaces vxlan vxlan903 firewall in name VXLAN903_IN
set interfaces vxlan vxlan903 firewall in ipv6-name VXLAN903_IN6

commit
save
```

| Step | Test | Pass criterion |
|---|---|---|
| 3.1 | `show configuration commands \| grep vxlan903` | the attachments are present |
| 3.2 | `show firewall name VXLAN903_IN`; `show firewall ipv6-name VXLAN903_IN6` | rulesets present |
| 3.3 | `sudo iptables -S VYATTA_FW_IN_HOOK` | exactly one `-i vxlan903 -j VXLAN903_IN` jump |
| 3.4 | `sudo ip6tables -S VYATTA_FW_IN_HOOK` | exactly one `-i vxlan903 -j VXLAN903_IN6` jump |
| 3.5 | IPv4 echo request from the overlay peer | permitted; counters increase |
| 3.6 | IPv4 TCP/UDP to a denied port | dropped; counters increase |
| 3.7 | IPv6 NDP (`ip -6 neigh`) and ICMPv6 echo | neighbour resolution works; echo permitted |
| 3.8 | IPv6 TCP to a denied port | dropped |
| 3.9 | `sudo /opt/vyatta/sbin/vyatta-vxlan-firewall --status vxlan903` | configured and effective pairs match |
| 3.10 | Traffic on the underlay interface (outer UDP/4789) | untouched by the overlay attachment |
| 3.11 | Traffic on an unrelated interface with its own policy | unchanged |

Repeat 3.1–3.10 for `local` and `out` attachments, with the correct native semantics:

* `local` filters packets destined to the router on ingress (`INPUT`, `-i vxlan903`);
* `out` filters forwarded packets leaving the interface (`FORWARD`, `-o vxlan903`);
* `in` filters forwarded packets arriving on the interface (`FORWARD`, `-i vxlan903`).

For `out`, generate traffic that is **forwarded** through the router and leaves `vxlan903`; locally
originated traffic from the router is not matched by the native `out` hook.

## 5. Recreation with active traffic

Start a continuous negative probe from the overlay peer to a **denied** destination on the router
(for example a TCP port that the policy drops) at 100 ms intervals, and a positive probe to a
permitted destination. Record both on the probe host and on the router with `tcpdump`.

| Step | Action | Pass criterion |
|---|---|---|
| 5.1 | Change `vni` (for example 903 -> 904), keeping the attachment | interface recreated; jump survives; negative probe never succeeds; positive probe resumes after the expected brief outage |
| 5.2 | Change the UDP port | same |
| 5.3 | Change `remote-ip` | same |
| 5.4 | Change the attachment and the VNI in the same commit | commit succeeds; new jump; no negative success |
| 5.5 | Inject a recreation failure (see Phase 6) while the attachment is configured | old interface and old dispatch restored, or interface left down; no negative success |

Use the ifindex to confirm recreation changed the netdevice while the iptables jump remained name-based.

## 6. Failure injection

All injections must be reversible and performed on the disposable test router with approval. Record the
exact commands.

1. **Invalid ruleset reference.** Set an attachment to a nonexistent ruleset. The commit must fail at
   validation, before any interface or firewall mutation. Verify the old jump and interface are
   unchanged.
2. **Attachment install failure.** Temporarily replace `/usr/sbin/ubnt-fw` with a wrapper that exits 1
   for `update-interface` and delegates all other commands (or use an equivalent controlled fault).
   Commit a new attachment. The commit must fail; the interface must not be operational without the
   attachment; the error must name the interface and attachment. Restore `ubnt-fw`.
3. **Reconciler failure with an attachment change.** Change the VNI and add a 256-character
   description in one commit (the alias step fails deterministically). Verify the interface is rolled
   back to the previous identity and the previous firewall jump is restored. If restoration is not
   possible, verify the interface is down and the error is explicit.
4. **Rollback failure.** Make both the creation and the restoration fail (for example block the
   `vxlan` module load after deletion, with a controlled test). Verify the interface is down, the
   error is explicit, and no traffic is forwarded.
5. **Verification failure.** Replace `iptables`/`ip6tables` with a wrapper that makes `-C` fail after
   a successful `ubnt-fw` update. The commit must fail and the interface must be down.

After each injection: restore the original files, run `commit` again, and verify convergence.

## 7. Saved configuration, cold boot, and fail-open detection

This is the most important security test. Use an external probe host that continuously sends a probe
that the attached policy **must deny** (for example IPv4 TCP/8080 to the router's overlay address, or
IPv6 TCP/8080). The probe must run at 100 ms intervals and log timestamps. A single success is a
failure.

| Step | Action | Pass criterion |
|---|---|---|
| 7.1 | `save` the working configuration with the attachments | saved |
| 7.2 | Cold boot (with approval) while the probe runs | no successful denied probe; after boot the interface is up and the jump is present |
| 7.3 | Inspect the boot loader/commit logs | no firewall attachment error; if there is one, the interface is down |
| 7.4 | `show configuration commands`, `show interfaces`, `--status` | configuration and effective state agree |
| 7.5 | Repeat the boot with the probe started before the router finishes booting | same; document the earliest observed success (must be none) |

If the native engine cannot provide a zero-exposure boot interval, record the exact interval and
mechanism; do not claim atomicity. The acceptable fallback is an interface that stays down until the
gate passes.

## 9. Regression

* Existing IPv4-underlay and IPv6-underlay VXLAN interfaces without attachments: creation, identity
  change, recreation, bridge membership, rollback, save/reboot.
* The existing bridge and MTU hardware tests remain valid; the firewall subtree must not affect them.
* `ip -j -d link show` remains the diagnostic; `ip -d` human output is known-broken and is not used for
  decisions.

## 10. Evidence to return

For each phase: command transcripts, `iptables-save`/`ip6tables-save` before and after, `show
configuration commands`, ifindex and interface state, firewall counters, probe logs with timestamps,
packet captures for the denied/permitted traffic, and the exact package versions. Mark each step
PASS / FAIL / NOT RUN. A passing configuration without dataplane evidence is not a pass.
