## What changed from RC2

RC3 is the remaining RC2 maintainer-review iteration; no new feature scope.

* Quiesce a change set that needs more than one sequential vendor dispatch operation; keep a single
  replacement or insertion nondisruptive. An operational interface no longer carries an
  intermediate dispatch combination.
* Install `EXIT` traps in the helper and reconciler while a firewall mutation is in flight. A
  configuration-API diagnostic after the mutation restores the pre-change dispatch and
  administrative state; a recreation runs the normal rollback; if the firewall cannot be restored,
  the interface is left down.
* Base the capture-failure gate on the previous (effective) configuration as well as the candidate.
  A candidate that removes the final attachment no longer makes an enforced interface look
  intentionally unfiltered; an unreadable previous state is fail-closed.
* Verify the terminal rule against the vendor `fw.cpp` default-action format: unconditional vendor
  comment, `accept`/`drop`/`reject` mapped to `RETURN`/`DROP`/`REJECT`, and, for desired state,
  agreement with the configured default action. Rollback checks shape and verdict consistency only.
  The vendor-owned policy trust boundary is documented.
* Hardware runbook: account for all runtime-only state (policy routing/table, delegated-prefix
  loopback address, interface-specific sysctls), separate the four evidence classes, and replace
  invalid multi-chain `iptables -S` invocations.
* Add the bounded first-hardware-session sequence
  (`docs/v0.3.0-first-hardware-session.md` and `scripts/first-hardware-session.sh`): inventory,
  backup, staging, installation and isolated `vxlan903` testing only.

Linux `4.14.54-UBNT`, MIPS little-endian. Do not install on another model, firmware or kernel.

session is reviewed and a maintenance window is approved.
