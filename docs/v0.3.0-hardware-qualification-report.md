# v0.3.0 — consolidated hardware qualification report

**Status:** hardware qualification of RC5 completed on the ER-X; final 0.3.0 release prepared from
the qualified payload. **No merge, tag or publication has been made yet.** Independent OCI external
probes remain deferred and are not claimed.

## 0. Qualification closure

* **RC5-exact evidence.** The stages 1–3 installation checks, the lifecycle scenario set, the
  interrupted-transaction analysis, the `vxlan41913` migration and the saved-configuration reboot
  were executed on the installed RC5 packages (`0.3.0~rc5+edgeos3.0.1.e50`).
* **Inherited evidence.** The RC3 off-device suite/emulated-engine results, the RC3 hardware
  stages 1–3 and the v0.2.2 hardware results are inherited from the earlier candidates; they were
  not re-executed against RC5. The six-combination dataplane matrix was executed on the RC3
  installation; RC5's changes (configured-rule presence and xtables lock wait) were exercised by
  the lifecycle runs and `--verify-all` on RC5, not by repeating the matrix.
* **Boot transition.** The planned **continuous negative boot-time probe was not executed.** The
  local boot qualification was management/service availability polling plus post-boot
  verification; it does not establish zero transient enforcement exposure during the boot
  transition. Internet-facing continuous probing remains deferred.
* **Observed behaviour vs guarantees.** The fail-closed paths, gate checks and recovery procedures
  were observed on hardware. The extension is not a continuous firewall integrity monitor, does not
  provide a general atomicity guarantee across arbitrary interruptions, and cannot protect against
  out-of-band changes to vendor-managed rulesets.
* **Package lifecycle.** Upgrades RC3→RC4→RC5 were qualified on hardware. Package **removal** and
  **downgrade** were **not** qualified; the post-publication RC5→0.3.0 upgrade was qualified after
  the release.
* **Deferred tests.** Independent Internet-facing (OCI) positive/negative probes, unsolicited
  inbound tests and forwarded dataplane tests from active delegated-prefix clients remain
  deferred. They are not a blocker for the generic VXLAN implementation but limit Internet-facing
  acceptance claims.

xtables lock ownership is handled by the RC5 `-w` wait; the commit completed without errors.

**Migration of `vxlan41913` (quiesced handover):** four native ingress attachments

deferred and not claimed.

**Persistence and reboot:** configuration saved with the native policy and **no** test
configuration (`saved_test=0`). After reboot: RC5 packages and modules present; saved configuration

## 3. Defects observed and resolutions

1. **EdgeOS 3.0.1 scripted-commit firewall defect** (vendor): scripted (script-template) commits
   misapply `firewall name` changes — `static` status, `-F` on the chain, default-action only; absent
   chain → commit fails, present chain → silent degradation. Interactive commits are correct.
   **Resolution:** documented limitation and support boundary
   (`docs/v0.3.0-edgeos-scripted-commit-limitation.md`, `docs/v0.3.0-support-boundary.md`); the
   package does not patch the vendor.
2. **Gate accepted a degraded chain** (extension): only non-empty + terminal default were checked.
   **Resolution:** RC4 verifies every configured rule number is present in the effective chain
   (bounded vendor-comment check); an unreadable rule list is an API failure.
3. **Xtables contention aborted a transaction** (extension): helper reads did not wait for the lock.
   **Resolution:** RC5 uses `-w` for every helper iptables/ip6tables call; regression test pins it.
4. **Vendor engine attachment registration** (vendor behaviour): a ruleset created in an earlier
   commit was refused by `ubnt-fw update-interface` until the attachment was materialised in a
   configuration session. **Resolution:** documented; the migration used the session-context engine
   call followed by the config commit. A future firmware/package change should make this
   unnecessary.
5. **Runtime-only table 41913 routes lost on interface recreation** (platform): RPDB, loopback and
   sysctls survived; the dedicated-table routes did not. **Resolution:** restoration script
   (`/config/rc5-post-save/restore-runtime.sh`, copied off-router) re-applies RPDB, table 41913,
   loopback address, interface sysctls and the `tun0` HE policy after boot.
6. **Boot ordering:** the reboot took ~4 minutes before SSH returned; the earlier refusal was the
   boot/config-application interval, not a service failure. Documented for operations.

## 4. Supported configuration workflows

See `docs/v0.3.0-support-boundary.md`: interactive firewall ruleset changes are supported; scripted
firewall ruleset changes are **not** supported on this platform; scripted VXLAN configuration
referencing existing, correctly materialised rulesets is supported; combined create+attach is
interactive-only; boot restoration is verified on this build; commit-confirm/rollback is supported
interactively.

## 5. Remaining vendor limitations and residual risks

* Scripted firewall configuration can silently degrade rulesets (vendor defect); do not use it.
* A ruleset edited by a scripted commit can be degraded until the next interface apply/verification.
* Abrupt termination without trap execution can leave the interface down with a partial dispatch
  set; recovery is a subsequent commit or the documented engine call.
* Runtime-only Route64 state (RPDB, table 41913, loopback test address, sysctls) must be restored
  after each reboot with the provided script.
* The `tun0` HE manual policy is not part of the saved configuration; its `HEv6` chains survive boot
  but the jumps must be re-added if absent (the restoration script does this).
* Persistent source-address-dependent routing remains a separate engineering concern and is not
  incorporated into edgeos-vxlan.

## 6. Deferred tests

Independent external (OCI) positive/negative probes, unsolicited inbound tests from the Internet,
and forwarded dataplane tests from active `/56` clients (no clients were active during the window)
remain **deferred**. Router-originated connectivity is not equivalent to these tests.
